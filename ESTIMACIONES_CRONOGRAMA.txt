11.6 CRONOGRAMA
================================================================================

El desarrollo de Inventrix se realizó en fases iterativas desde noviembre 2025
hasta junio 2026 (7 meses). A continuación se presenta el cronograma real de
desarrollo y el plan proyectado de versiones futuras.

────────────────────────────────────────────────────────────────────────────────
11.6.1 CRONOGRAMA DE DESARROLLO REAL (nov 2025 – jun 2026)
────────────────────────────────────────────────────────────────────────────────

  FASE 1 — Fundamentos del sistema                       Nov 2025
  ┌──────────────────────────────────────────────────────────────────────────┐
  │ • Inicialización del proyecto (Django + React + PostgreSQL)              │
  │ • Configuración de despliegue (Vercel, Dokploy)                          │
  │ • Módulo de inventario base (productos, stock)                           │
  │ • Modo oscuro y navegación responsiva                                    │
  │ • Migración de Netlify a Vercel                                          │
  └──────────────────────────────────────────────────────────────────────────┘

  FASE 2 — Operaciones principales                   Dic 2025 – Mar 2026
  ┌──────────────────────────────────────────────────────────────────────────┐
  │ • Ventas y órdenes de compra con serializers avanzados                   │
  │ • Integración de bitácora de servicios con almacenamiento R2             │
  │   (Cloudflare): fotos en recepción, diagnóstico, reparación y entrega    │
  │ • Actualización de dependencias (react-router-dom v7)                    │
  └──────────────────────────────────────────────────────────────────────────┘

  FASE 3 — Enriquecimiento y auditoría               Abr – May 2026
  ┌──────────────────────────────────────────────────────────────────────────┐
  │ • Dashboard rediseñado                                                    │
  │ • Sistema de auditoría con triggers PL/pgSQL en PostgreSQL               │
  │ • Logs de auditoría en la UI                                             │
  │ • Filtros de proveedores y ordenamiento en productos                     │
  │ • Sistema completo de garantías y reclamaciones (3 fases)                │
  │ • Optimización de carga (queries N+1, caché, code splitting)             │
  │ • Corrección de migraciones en producción (502 repair)                   │
  │ • Gestión de proveedores en productos; órdenes de compra mejoradas       │
  └──────────────────────────────────────────────────────────────────────────┘

  FASE 4 — Módulos financieros y operativos          Jun 2026 (semana 1-2)
  ┌──────────────────────────────────────────────────────────────────────────┐
  │ • Pago por adelantado / abonos con estado de pago y saldo pendiente      │
  │ • Cuentas por Cobrar con aging y recordatorio WhatsApp                   │
  │ • Cotizaciones / proformas con conversión a venta y PDF                  │
  │ • Devoluciones / notas de crédito con reingreso de stock                 │
  │ • Recibos y comprobantes de pago en PDF                                  │
  │ • Módulo de Respaldos con un clic                                        │
  └──────────────────────────────────────────────────────────────────────────┘

  FASE 5 — POS, análisis e importación               Jun 2026 (semana 3)
  ┌──────────────────────────────────────────────────────────────────────────┐
  │ • Punto de Venta (POS) con escáner de código de barras (cámara)          │
  │ • Etiquetas con código de barras imprimibles (jsbarcode)                 │
  │ • Reporte de rentabilidad por producto y stock muerto                    │
  │ • Importación masiva de productos desde CSV/XLSX                         │
  │ • Fix del reporte de ventas: productos y tipo (servicio/producto)        │
  └──────────────────────────────────────────────────────────────────────────┘

  FASE 6 — Autenticación y seguridad                 Jun 2026 (semana 4)
  ┌──────────────────────────────────────────────────────────────────────────┐
  │ • Login con JWT (djangorestframework-simplejwt + token_blacklist)        │
  │ • API protegida globalmente con IsAuthenticated                          │
  │ • Gestión de usuarios (roles: Administrador / Usuario)                   │
  │ • Throttling anti fuerza bruta (5 intentos/min en login)                 │
  │ • Cabeceras de seguridad (CSP, HSTS, X-Frame-Options) en Vercel          │
  │ • Purga de secretos del historial git (git filter-repo)                  │
  │ • Auditoría de seguridad completa con plan de remediación (Scrum)        │
  └──────────────────────────────────────────────────────────────────────────┘
