INTRODUCCIÓN
  Este documento evalúa la viabilidad técnica de encargar el desarrollo del
  sistema Inventrix a un equipo externo de desarrolladores de software. Se
  analiza si la tecnología propuesta es adecuada, si el equipo contratado
  cuenta con las capacidades necesarias, si la infraestructura requerida es
  accesible para el cliente, y cuáles son los riesgos técnicos a considerar
  antes de aprobar el proyecto.

  El estudio responde a la pregunta: ¿Es técnicamente posible construir y
  mantener este sistema con los recursos y tecnologías disponibles?

================================================================================
1. DESCRIPCIÓN TÉCNICA DEL SISTEMA SOLICITADO
================================================================================

  El cliente requiere una aplicación web de gestión empresarial que integre:
  control de inventario, registro de ventas y compras, gestión de clientes y
  proveedores, y una bitácora fotográfica de servicios para motos. El sistema
  debe ser accesible desde navegadores web en cualquier dispositivo, sin
  necesidad de instalar software en las computadoras del negocio.

  Tipo de sistema: Aplicación web SPA (Single Page Application)
  Modelo de acceso: Navegador web (Chrome, Firefox, Edge, Safari)
  Modelo de despliegue propuesto por el equipo de desarrollo:
    - Frontend: Vercel (plataforma en la nube, sin servidor propio)
    - Backend:  Servidor VPS con contenedor Docker y Gunicorn
    - Base de datos: PostgreSQL 16
    - Almacenamiento de imágenes: Cloudflare R2 (servicio en la nube)

3. ARQUITECTURA DEL SISTEMA
================================================================================

  El equipo de desarrollo propone una arquitectura de tres capas desacopladas,
  lo que significa que cada parte del sistema puede actualizarse o reemplazarse
  de forma independiente sin afectar las demás.

  ┌──────────────────────────────────────────────────────────────────┐
  │  INTERFAZ DE USUARIO (Frontend)                                  │
  │  React 19 + Vite 7 → alojado en Vercel                          │
  │  El usuario accede desde cualquier navegador web                 │
  └────────────────────────┬─────────────────────────────────────────┘
                           │ Conexión segura HTTPS
  ┌────────────────────────┴─────────────────────────────────────────┐
  │  SERVIDOR DE APLICACIONES (Backend)                              │
  │  Django 6 + Django REST Framework                                │
  │  Procesa la lógica del negocio: ventas, inventario, reportes     │
  └─────────────┬──────────────────────────┬────────────────────────┘
                │                          │
  ┌─────────────┴──────────┐  ┌────────────┴───────────────────────┐
  │  BASE DE DATOS         │  │  ALMACENAMIENTO DE IMÁGENES        │
  │  PostgreSQL 16         │  │  Cloudflare R2                     │
  │  Productos, clientes,  │  │  Fotos de bitácora de servicios    │
  │  ventas, compras,      │  │  e imágenes de productos           │
  │  auditoría, etc.       │  └────────────────────────────────────┘
  └────────────────────────┘

  Ventaja de esta arquitectura para el cliente:
    - Si el proveedor de hosting del frontend cambia de precio, solo se
      migra esa capa sin tocar el resto del sistema.
    - Si se requiere cambiar el proveedor de imágenes (R2), el resto del
      sistema no se ve afectado.
    - El equipo puede trabajar en el frontend y el backend en paralelo,
      acortando los tiempos de entrega.

6. SEGURIDAD TÉCNICA DEL SISTEMA
================================================================================

  El equipo de desarrollo debe garantizar las siguientes medidas de seguridad,
  que el cliente debe verificar en la entrega:

  Aspecto               Medida exigida al equipo
  ─────────────────────────────────────────────────────────────────────
  Credenciales y        Ninguna contraseña ni clave de acceso debe estar
  secretos              escrita directamente en el código fuente. Deben
                        usarse variables de entorno en el servidor.

  Control de acceso     La API del backend no debe ser accesible sin
  a la API              autenticación para operaciones de escritura. El
                        sistema de login debe implementarse antes del
                        despliegue en producción.

  Protección contra     El framework Django protege por defecto contra
  ataques comunes       inyección SQL, XSS y CSRF. El equipo debe
                        mantener estas protecciones activas.

  Validación de datos   Todo dato ingresado por el usuario debe validarse
                        tanto en el navegador como en el servidor antes
                        de guardarse en la base de datos.

  HTTPS                 El sistema completo debe operar bajo HTTPS en
                        producción. Ninguna comunicación en texto plano.

  Auditoría             El sistema debe registrar automáticamente cualquier
                        modificación a los datos de productos mediante
                        triggers de base de datos, sin posibilidad de
                        alterar ese historial.

  Backups               El equipo debe entregar un procedimiento documentado
                        de respaldo y restauración de la base de datos.

10. CRITERIOS DE ACEPTACIÓN TÉCNICA PARA LA ENTREGA
================================================================================

  El cliente debe verificar los siguientes puntos antes de dar por aceptado
  el sistema y realizar el pago final al equipo de desarrollo:

  [ ] El sistema funciona correctamente en Chrome, Firefox y Edge.
  [ ] La interfaz se adapta correctamente en celular, tablet y computadora.
  [ ] Todos los módulos del sistema operan sin errores críticos.
  [ ] El sistema cuenta con HTTPS activo en producción.
  [ ] Los backups automáticos están configurados y se ha probado la
      restauración al menos una vez.
  [ ] El código fuente está disponible en el repositorio GitHub del cliente.
  [ ] El equipo entrega las credenciales del servidor VPS, Vercel,
      Cloudflare R2 y GitHub al cliente.
  [ ] Se entrega documentación de despliegue para futuras actualizaciones.
  [ ] El sistema de autenticación de usuarios está implementado y funcional.
  [ ] Los triggers de auditoría de base de datos están activos y registrando
      cambios correctamente.

11. CONCLUSIÓN DE FACTIBILIDAD TÉCNICA
================================================================================

  VEREDICTO: TÉCNICAMENTE FACTIBLE — SE RECOMIENDA PROCEDER

  El sistema Inventrix puede ser construido con tecnologías maduras, gratuitas
  y ampliamente soportadas. Las conclusiones del estudio son:

    [✓] El stack tecnológico propuesto (Django + React + PostgreSQL) es
        estándar en la industria, con abundante documentación y soporte
        comunitario global.

    [✓] No se requiere ningún software propietario ni licencias de pago
        para el desarrollo ni para la operación del sistema.

    [✓] La infraestructura de producción es accesible para una PyME:
        no se necesita administrar servidores complejos ni contratar
        personal técnico permanente.

    [✓] El cliente conserva la propiedad del código fuente, lo que
        elimina la dependencia del equipo de desarrollo original.

    [✓] La arquitectura es escalable y puede crecer con el negocio sin
        necesidad de reescribir el sistema.

    [!] Condición técnica prioritaria: el sistema de autenticación de
        usuarios debe incluirse en el alcance del contrato antes del
        despliegue en producción. Sin este módulo, cualquier persona
        con acceso a la URL del sistema podría ver y modificar los datos.

  Se recomienda al cliente incluir en el contrato de desarrollo una cláusula
  de entrega del código fuente, credenciales de infraestructura y
  documentación técnica como condición de pago del último hito.
